> 사람은 대부분 web 환경에서 일을 한다. AI도 WEB 환경에서 일을 해야 한다.
> 하지만 세상은 그것을 막는다. 그것을 가능하게 만들어야 한다. 그래야 자동화가 된다.
> **인간은 반복적이고 지겨운 일에서 해방되어야 한다. 그래서 만들었다.**

## 왜 만들었나

웹사이트는 **사람을 위해** 만들어졌다. 그렇다면 그 위에서 일하는 자동화도 사람과 **같은 방식**이어야 한다.
API가 없어도, 통합이 없어도, 사람이 로그인해서 클릭하고 읽고 입력하는 모든 일을 — AI가 대신한다.

기존 자동화는 사이트마다 셀렉터를 손으로 박아 넣는 취약한 규칙 덩어리였다.
사이트가 조금만 바뀌어도 무너진다. 우리는 다른 길을 택했다.

## 핵심 철학 — 화면 위의 자율주행

테슬라 FSD가 30만 줄의 규칙 코드를 버리고 **카메라로 도로를 보는 종단간 학습**으로 간 것처럼,
webagent_ABI는 셀렉터 하드코딩 대신 **화면을 눈으로 보고 판단하는** 에이전트다.

| 사람 | webagent_ABI | 도로 위 자율주행 |
|---|---|---|
| **눈** — 화면을 본다 | 스크린샷 + 접근성 트리 | 카메라 비전 |
| **머리** — 무엇을·왜·어떻게 판단 | LLM 추론 (IQ를 극대화) | Occupancy / Planner |
| **손** — 클릭·입력·이동 | 브라우저 자동화 도구 | 조향·가감속 |
| **일머리** — 그 사이트에서 일하는 순서 | 워크플로우 학습 → 스킬 | 사람 운전에서 모방학습 |

### 두 개의 모드, 하나의 원칙

> **웹 UI에서는 사람처럼(브라우저), 결과를 만들 때는 코딩으로(속도·품질).**

- **상호작용 = 사람처럼**: 로그인된 실사이트를 눈으로 보고 판단하며 조작한다. UI는 사람용이니까.
- **생산 = 코딩으로**: 산출물(표·문서·분석)은 클릭이 아니라 코드로. 유능한 개발자가 매크로를 짜듯, 빠르고 정확하고 재현 가능하게.

이것이 지금 이 시점에 AI를 쓰는 이유다.

## 뼈대 4축

1. **지각→판단→행동 폐루프** — 매 스텝 화면을 보고(캡처) 판단하고 행동한 뒤 다시 본다. 눈 감고 클릭하지 않는다.
2. **메모리 체계** — 사람 직원처럼 세 겹의 기억: 무엇을 아는가(지식·fact) / 어떻게 더 잘하는가(방법·method) / 무슨 일을 받았는가(업무). 한 번 배우면 다시 찾지 않는다.
3. **스킬 체계** — 사람이 오피스 프로그램을 다루듯, 필요한 기술을 **보유하고 필요할 때 로딩**한다. 재발명하지 않는다.
4. **검색 = 첫 기술, 자기성장** — 모르면 먼저 찾는다. 필요한 기술이 무엇인지 스스로 알고, 찾아서, 장착한다.

## 안전이 먼저다

로그인된 계정에 접근하고, 신뢰할 수 없는 웹 콘텐츠를 읽고, 외부와 통신하는 에이전트는
**치명적 3요소(lethal trifecta)** 를 모두 가진 고위험 존재다. 그래서 강력한 기능을 열기 **전에** 하네스를 세운다.

- **콘텐츠 = 데이터 경계** — 페이지·이메일·URL의 텍스트는 분석 대상일 뿐, 절대 지시가 아니다. (간접 프롬프트 인젝션 방어)
- **유출 방지** — 쿠키·데이터를 외부로 실어 보내는 스크립트를 코드 레벨에서 차단.
- **승인 게이트** — 되돌리기 어려운 행동(발송·삭제·결제) 전에는 멈추고 사람의 승인을 기다린다.
- **최소 권한 · 샌드박스 · 감사 로그** — 모든 작업은 기록되고, 코드 실행은 격리된다.

공개된 실제 사고(EchoLeak, Comet 인젝션 등)를 연구해 설계에 반영했다. 자세한 내용은 [`docs/SECURITY.md`](docs/SECURITY.md).
