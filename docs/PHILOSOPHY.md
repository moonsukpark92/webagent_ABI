# 설계 철학

webagent_ABI는 다섯 개의 원칙 위에 서 있다. 하나의 문장으로 줄이면:
**"웹 UI에서는 사람처럼, 결과를 만들 때는 코딩으로."**

## A. 사람처럼 — 눈·머리·손

웹사이트는 사람을 위해 만들어졌다. 그러므로 그 위의 자동화도 사람과 같은 로직이어야 한다.

- **눈** — 화면을 본다: 스크린샷(픽셀 시각) + 접근성 트리(구조·텍스트).
- **머리** — 판단한다: 화면을 읽고 다음 행동을 결정하고, 예외·함정을 식별한다.
- **손** — 조작한다: 클릭·입력·이동·다운로드.

핵심은 이 셋을 잇는 **지각→판단→행동 폐루프**다. 페이지 이동 직후와 중요한 클릭 전후에는
반드시 화면을 다시 보고, 화면과 예상이 일치할 때만 행동한다. 눈 감고 클릭하지 않는다.

그리고 부족한 한 가지 — **그 사이트에서 사람이 일하는 순서(워크플로우)를 먼저 배우는 것**.
즉흥 클릭이 아니라, 관찰로 절차를 파악해 스킬로 굳히고, 다음부터 재현한다.

## B. 화면 위의 자율주행 — FSD의 교훈

자율주행은 HD맵(사전에 모든 도로를 손으로 박아넣기)이라는 지름길 대신
**카메라로 도로를 보는 종단간 학습**으로 갔다. 웹 자동화도 같다.

- **비전 우선**: DOM 셀렉터·API는 보조. 렌더된 화면을 사람처럼 본다. 사이트가 바뀌어도 눈으로 적응한다.
- **모방학습**: 사람의 시연·개입이 곧 학습 데이터다. 개입 지점(로그인·인증·교정)이 학습 신호가 된다.
- **플릿 학습**: 한 에이전트가 배운 워크플로우를 전체가 공유한다. 한 번 배우면 모두가 빨라진다.
- **매 스텝 재지각**: 행동 후 반드시 화면을 다시 본다.

## C. 메모리 체계 — 사람 직원처럼 안다

사람 직원은 회사를 알고, 요령이 늘고, 받은 일을 기억한다. 에이전트도 세 겹의 기억을 갖는다.

1. **지식(fact)** — 사이트 구조·로그인 방식·규칙·함정. "그 사이트를 안다."
2. **방법(method)** — 더 쉽고 빠르게 하는 법, 실패 회피, 개입 교훈. "일머리."
3. **업무(task)** — 누가 무슨 일을 언제까지 줬는지, 맥락과 상태.

학습 루프: 보고(캡처) → 행동 → fact·method 추출 → 저장 → 재사용.
**메모리가 성장의 복리를 만든다.** 한 번 배운 것은 다시 찾지 않는다.

## D. 스킬 체계 — 필요한 기술을 보유하고 로딩한다

사람이 엑셀·PPT를 다루듯, 에이전트는 기술을 갖춘다. 기술은 이미 세상에 나와 있다 — **재발명하지 않는다.**

- **자체 스킬**: 도메인·업무 유형에 따라 자동 주입되는 절차(검색·문서작성·보고서 양식·스크리닝 방법론 등).
- **외부 공식 스킬**: 파일 산출물(스프레드시트·문서·PDF·차트)은 검증된 공식 스킬을 필요할 때 로딩해 쓴다.
- 스킬 = **절차**(단계 + 판단 지점 + 성공 기준 + 가드레일).

## E. 검색 = 첫 기술, 그리고 자기성장

모르면 먼저 찾는다. 검색·분석이 모든 업무의 출발점이다.

**자기성장 루프**: 업무를 받으면 → 필요 역량을 분해하고 → 보유 스킬·메모리와 대조해 **갭을 식별**하고 →
갭이 있으면 검색으로 조사해(공식 스킬이 있으면 로딩, 없으면 조사 결과로 새 스킬 초안) → 검증·검수 후 등재하고 →
그 스킬로 수행하며 더 나은 방법을 메모리에 축적한다.

LLM의 높은 지능을 규칙으로 가두지 말고 판단에 맡기되, 스킬과 메모리로 보강해 **스스로 크게** 만든다.

## 하나의 원칙으로: 상호작용은 사람처럼, 생산은 코딩으로

| 모드 | 무엇에 | 왜 | 어떻게 |
|---|---|---|---|
| **상호작용 = 사람처럼** | 로그인 웹앱 접근·읽기·탐색·조작 | UI는 사람용 | 눈·머리·손 (A/B) |
| **생산 = 코딩** | 산출물 생성·데이터 처리·분석·문서 | 클릭은 느리고 깨짐, 코드는 빠르고 정확·재현 | 스크립트 + 공식 스킬 |

판별: "웹에서만 얻을 수 있는가"(→브라우저) vs "데이터를 가공해 결과물을 만드는가"(→코드).

## 산출물의 기본 양식

모든 보고·문서는 **피라미드 원칙**(결론 먼저) · **MECE** · **액션 타이틀**(제목이 곧 결론) 을 따른다.
보기 좋고, 시인성 높고, **핵심이 3초 안에 보여야** 한다. 데이터는 표보다 차트로.
